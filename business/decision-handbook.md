## 决策分层

### 三层决策模型

```
┌─────────────────────────────────────────┐
│ Layer 1: 一次性决策（现在就做）         │
├─────────────────────────────────────────┤
│ - 目标客户是谁 ✅ 已决定                │
│ - 卖什么产品 ✅ 已决定                  │
│ - 定价是多少 ✅ 已决定                  │
│ - 主要渠道 ✅ 已决定                    │
└─────────────────────────────────────────┘
            ↓ （不需要再思考）
┌─────────────────────────────────────────┐
│ Layer 2: 规则化决策（有规则就执行）     │
├─────────────────────────────────────────┤
│ - 今天写什么内容 ✅ 有规则              │
│ - 什么时间发布 ✅ 有规则                │
│ - 怎么回复客户 ✅ 有模板                │
│ - 什么时候跟进 ✅ 有节奏               │
└─────────────────────────────────────────┘
            ↓ （查规则手册）
┌─────────────────────────────────────────┐
│ Layer 3: 即时决策（真正需要思考的）     │
├─────────────────────────────────────────┤
│ - 客户提出定制需求                       │
│ - 竞争对手出招                           │
│ - 市场发生重大变化                       │
└─────────────────────────────────────────┘

目标：
- Layer 1 一次性决策 → 做 1 次，用 1 年
- Layer 2 规则化决策 → 90% 的日常执行
- Layer 3 即时决策 → 每周 < 5 次
```

## 内容决策自动化

### 写什么（有规则就不思考）

```
规则 1：内容日历（提前规划）

每周固定：
- 周一：工具深度分析（如 OpenSpec）
- 周三：行业洞察解读（如 Karpathy 推文）
- 周五：实战案例分享（如"我用 AI 编程 30 天"）

不需要每次思考"今天写什么"，查日历就行。

---

规则 2：选题矩阵（有矩阵就不犹豫）

| 内容类型 | 发布频率 | 优先级 | 理由 |
|---------|---------|--------|------|
| 工具深度分析 | 月度 | 高 | 建立权威 |
| 行业洞察解读 | 周度 | 中 | 追热点 |
| 实战案例分享 | 周度 | 中 | 获客 |
| 对比评测 | 季度 | 低 | 竞品多时做 |

不需要每次选择选题，看矩阵就行。

---

规则 3：内容模板（填空式创作）

工具分析模板：
```
标题：[工具名] [版本号] 深度解析：[核心变革]

开篇：[发布时间]发布的 [工具名] [版本] 标志着...

核心洞察：
- 变革 1
- 变革 2
- 变革 3

个人使用体验：
- 使用时间：[X周/X月]
- 对比工具：[工具A vs 工具B]
- 真实感受：[3个核心感受]

核心问题与解决方案：
- 问题一：[问题名]
- 解决方案：[解决方案]

商业/行业洞察：
- 趋势 1
- 趋势 2

可执行工具包：
- 步骤 1
- 步骤 2

CTA：[明确的行动号召]
```

不需要每次构思结构，填空就行。

---

规则 4：热点响应机制

触发条件：
- Karpathy 发推文 → 24 小时内出解读
- OpenSpec/SpecKit 大版本 → 3 天内出深度分析
- 行业大事件 → 1 周内出分析

不需要纠结"要不要追热点"，有规则就执行。
```

## 客户决策自动化

### 谁是目标客户（有画像就不筛选）

```
目标客户画像（Tier 1 - 优先级最高）：

特征：
- 50-500 人的技术团队
- 已经在用 AI 编程（Claude Code / Cursor / Copilot）
- 遇到问题（效率不达预期、不知道怎么用好）
- 有决策权（CTO / 技术VP）

行为信号：
- 主动询问"你用过 X 工具吗？"
- 询问"怎么落地 AI 编程？"
- 询问"你们用什么工具？"

非目标客户（不浪费时间）：
- 个人开发者（推荐付费课程）
- 非技术公司（推荐其他服务）
- 只问问不行动的（放入培育池）
```

### 如何回应咨询（有模板就不纠结）

```
场景 A：询问工具对比
→ 回复："我做了一份深度对比分析，包含了 5 个维度。如果需要，我可以发给你看看，先了解您现在的团队情况吗？"
→ 目的：收集需求信息

场景 B：询问企业培训
→ 回复："我的培训是实战导向的，需要先了解你们团队现状。能简单说说：1）多少人？2）现在用什么工具？3）主要痛点是什么？"
→ 目的：预筛选客户

场景 C：询问年度服务
→ 回复："年度服务是我的高端产品，需要深入合作。我会在前 1 个月提供深度诊断和实施路线图。如果这对你有价值，我们可以约个 30 分钟通话。"
→ 目的：筛选高意向客户
```

### 定价怎么说（有标准就不解释）

```
分析报告：
- 2-5 万/个
- 无折扣（这是建立信任的定价）
- 可以拆分为：50% 定金 + 50% 交付后

企业培训：
- 1 天：5 万
- 2 天：10 万
- 定制：20 万起
- 说明：价格包含前期调研、培训、课后答疑

年度服务：
- 50-100 万/年
- 按季度付款
- 包含：季度评估、月度培训、实时咨询

如果对方觉得贵：
- "我可以先做一个免费的 30 分钟诊断，你看看是否有价值，再说价格。"
```

## 定价决策自动化

### 统一定价表（不再纠结价格）

```
免费（获客）：
- 深度文章
- 社群答疑
- 30 分钟诊断（前 10 个客户）

低价（转化）：
- 工具分析报告：2-5 万
- 企业诊断：1 万

中价（现金流）：
- 1 天培训：5 万
- 2 天培训：10 万
- 定制培训：20 万起

高价（主要收入）：
- 年度服务：50-100 万/年

规则：
- 不打折（除了年度服务可以季度支付）
- 不议价（除非是年度大单）
- 不退款（除非质量问题）
```

### 折扣规则（有条件就不思考）

```
年度服务折扣（提前付款）：
- 一次性付清：9 折
- 半年付清：9.5 折
- 按季度：原价

推荐奖励：
- 推荐一个企业客户：返 10%
- 推荐成功案例展示：95 折

不提供：
- "学生优惠"（我们不做学生生意）
- "非盈利折扣"（这是商业服务）
- "试用后付费"（前期工作需要成本）
```

## 日常 SOP

### 每日清单（30 分钟完成）

```
早晨（15 分钟）：
□ 检查 Twitter/X 和即刻 @ 提及
□ 回复所有评论和私信（用模板）
□ 记录到客户追踪表

晚上（15 分钟）：
□ 查看 1 个 AI 工具更新（如果是大版本）
□ 记录到选题列表
□ 更新内容日历

周末（1 小时）：
□ 写下周的内容（1 篇文章）
□ 更新客户追踪表
□ 回顾本周数据，下周调整
```

### 每周清单（2 小时完成）

```
周一：
□ 发布工具分析文章（公众号）
□ 发布 Thread 版本（Twitter）
□ 发布精简版（即刻）

周三：
□ 发布行业洞察文章
□ 更新社群

周五：
□ 发布实战案例
□ 整理本周线索

周日：
□ 规划下周内容
□ 回顾本周数据
□ 调整策略（如果需要）
```

### 每月清单（4 小时完成）

```
第 1 周：
□ 更新客户追踪表
□ 跟进所有 Tier 1 客户
□ 复盘上月数据

第 2 周：
□ 规划本月内容
□ 制作 1 个"内容日历"

第 3 周：
□ 分析竞争对手动态
□ 调整策略（如果需要）

第 4 周：
□ 月度复盘
□ 更新 SOP（如果需要）
```

## 例外处理

### 什么情况下需要打破规则

```
规则优先级：

优先级 1：健康和人际关系
- 如果身体不适，休息
- 如果家庭需要时间，陪伴

优先级 2：现有客户的交付质量
- 如果客户需要，暂停获客
- 如果交付压力大，降低内容频率

优先级 3：重大市场变化
- 如果出现颠覆性工具，调整分析
- 如果市场风向改变，调整策略

规则不是枷锁，而是指南。
```

### 什么情况下需要即时决策

```
需要思考的情况（< 5%的情况）：

1. 客户提出定制需求
   → 评估：是否符合目标客户画像？
   → 评估：是否有可复用性？
   → 决策：接 or 不接

2. 竞争对手出招
   → 评估：是否影响核心价值？
   → 评估：是否需要回应？
   → 决策：关注 or 忽视

3. 市场重大变化
   → 评估：是否影响商业模式？
   → 评估：是否需要调整方向？
   → 决策：坚持 or 转型

其他情况 → 查手册
```

## 使用方法

### 第一次阅读

```
1. 把整个手册通读一遍
2. 理解决策分层逻辑
3. 记住"有规则就不思考"
```

### 每次使用

```
遇到问题 → 查相应章节 → 执行规则
（大部分情况下，查完就知道怎么做）

如果手册里没有：
→ 这是一个"例外"
→ 记录下来
→ 更新手册
→ 下次就有规则了
```

### 定期更新

```
每月底：
- 回顾本月决策
- 哪些决策可以固化为规则？
- 哪些规则需要调整？
- 更新手册
```
