# DeepSeek Engram 解析：如何将经典的 N-gram 变成大模型的“快速查词手册”？

> **TL;DR**: DeepSeek 团队提出了一种名为 **Engram** 的新型条件记忆（Conditional Memory）模块，通过将经典的 N-gram 结构与现代 Transformer 结合，为 LLM 引入了高效的知识查找原语。它能显著提升模型在知识检索、通用推理及长文本处理上的表现，且推理开销极低。

## 预备知识 (Prerequisite Knowledge)

为了更好地理解 Engram 的设计初衷，我们需要先了解以下核心概念：

### 什么是 N-gram？

**N-gram** 是自然语言处理（NLP）中一种经典的统计语言模型。它的核心思想非常直观：**预测下一个词时，只考虑它前面的 $N-1$ 个词。**

- **1-gram (Unigram)**：不考虑上下文，每个词独立出现。
- **2-gram (Bigram)**：预测当前词时，只看前 1 个词。例如，“Alexander”后面接“the”的概率。
- **3-gram (Trigram)**：预测当前词时，看前 2 个词。例如，“Alexander the”后面接“Great”的概率。

在深度学习流行之前，N-gram 是构建语言模型的主流方法。虽然它无法捕捉长距离的语义依赖，但在处理**局部、静态且高度模式化**的文本（如固定搭配、命名实体）时，N-gram 非常高效。Engram 正是重新挖掘了这一经典结构的潜力，将其作为一种高效的查找原语集成到现代 Transformer 中。

### 什么是条件计算 (Conditional Computation)？

**条件计算** 是一种旨在提高模型效率的设计理念。在传统的“稠密”模型中，处理每一个输入（如一个单词）时，模型的所有参数都会参与计算。这就像是一个工厂，无论生产什么产品，所有机器都必须同时运转，非常耗能。

条件计算则主张：**根据输入内容的不同，只激活模型中一小部分相关的参数。**

- **Mixture-of-Experts (MoE)** 是条件计算最成功的实现。它将模型层划分为多个“专家”，对于每个 Token，由一个路由器（Router）决定将其发送给哪几个专家处理。
- **优势**：可以在保持计算量（FLOPs）不变的情况下，极大地增加模型的总参数量（容量），从而让模型学到更多知识。

Engram 提出的 **条件记忆 (Conditional Memory)** 实际上是条件计算思想的延伸：MoE 是在“计算”维度进行稀疏激活，而 Engram 是在“存储/查找”维度进行稀疏检索。

## 问题陈述：Transformer 的“计算模拟检索”困境

目前的语言模型主要通过混合专家模型（MoE）来实现条件计算（Conditional Computation），从而在不显著增加计算量的情况下提升模型容量。然而，Transformer 架构缺乏一种原生的“知识查找”原语。

在处理命名实体（如 "Alexander the Great"）或公式化模式时，模型往往需要消耗多个早期层的注意力和前馈网络来重新构建这些静态信息。这种“通过计算模拟检索”的过程非常低效，浪费了宝贵的网络深度，而这些深度本可以用于更高层次的逻辑推理。

## 核心思想：条件记忆（Conditional Memory）

为了解决上述问题，作者提出了 **条件记忆（Conditional Memory）** 这一新的稀疏化维度。

- **条件计算 (MoE)**：稀疏激活参数以处理动态逻辑。
- **条件记忆 (Engram)**：通过稀疏查找操作检索静态嵌入，以获取固定知识。

**Engram** 模块通过 N-gram 嵌入实现 $O(1)$ 时间复杂度的查找。它将局部上下文作为 Key，通过哈希函数在海量的嵌入表中检索对应的向量。

### Engram 是如何实现的？（深度解析图 1）

结合图 1，我们可以将 Engram 的实现过程分为三个核心阶段：

#### 1. 检索阶段 (Retrieval Phase)
- **输入处理**：当模型处理到某个位置（如 "Great"）时，它会提取该位置的后缀 N-gram（如 2-gram "the Great" 和 3-gram "Alexander the Great"）。
- **哈希映射 (Hash)**：为了处理海量的 N-gram 组合，Engram 使用了 **多头哈希** 技术。每个 N-gram 会被映射到嵌入表中的特定索引。
- **静态嵌入提取**：根据哈希索引，从预先训练好的海量嵌入表中提取对应的向量（2-Gram Embedding 和 3-Gram Embedding）。这些向量存储了关于该模式的静态知识。

#### 2. 融合阶段 (Fusion Phase)
- **上下文感知门控 (Context-aware Gating)**：这是最关键的一步。检索到的静态嵌入虽然包含知识，但缺乏上下文。
    - 模型利用当前的 **隐藏状态 (Input Hidden)** 作为 Query。
    - 将检索到的记忆向量通过线性变换（Linear）生成 Key 和 Value。
    - 通过 **Scaled Dot Product** 计算出一个门控值（Gate）。
- **动态调节**：如果检索到的记忆与当前上下文语义一致，门控值就大；如果冲突（例如哈希碰撞导致的错误检索），门控值就趋近于 0。

#### 3. 集成阶段 (Integration Phase)
- **轻量级卷积 (Conv)**：融合后的向量会经过一个短的因果卷积，以进一步增强局部非线性表达。
- **残差连接**：最后，Engram 的输出通过残差连接合并回主干网络，并传递给后续的 Attention 和 MoE 层。

**总结**：Engram 就像是给 Transformer 装上了一个“快速查词手册”。它不再需要通过复杂的注意力计算去反复确认 "Alexander the Great" 是谁，而是直接从手册中查出结果，并由门控机制确认该结果是否适用于当前语境。

## 关键技术细节

Engram 并非简单的 N-gram 查找，它包含了多项现代化的改进，使其能够真正融入大规模预训练：

1.  **分词器压缩 (Tokenizer Compression)**：
    - **痛点**：标准分词器（如 BPE）为了保证无损还原，常给语义相同的词分配不同 ID（如 "Apple"、" apple"、"APPLE"）。这会稀疏化 N-gram 的统计分布。
    - **方案**：Engram 引入了一个映射函数，将这些 Token 映射到同一个“规范 ID”。这使得有效词表缩小了 **23%** ，极大地提高了记忆的利用率和语义密度。

2.  **多头哈希 (Multi-Head Hashing)**：
    - **痛点**：直接为所有可能的 N-gram 组合分配参数是不现实的（组合爆炸）。哈希查找虽然高效，但存在“哈希冲突”（两个不同的词组映射到同一个向量）。
    - **方案**：借鉴了 Transformer 的多头注意力思想，为每个 N-gram 阶数设置多个独立的哈希头。即使一个头发生了冲突，其他头仍能提供准确的信息，从而显著增强了系统的鲁棒性。

3.  **上下文感知门控 (Context-aware Gating)**：
    - **痛点**：静态记忆是“死”的，它不知道当前的语境。例如 "Apple" 在科技新闻和水果摊上的含义完全不同。
    - **方案**：利用当前层的隐藏状态作为 **Query**，去“询问”检索到的记忆。通过点积计算出一个 0 到 1 之间的门控值。只有当记忆与当前语境匹配时，信息才会被允许注入。这解决了歧义性问题，并能自动过滤哈希冲突产生的噪声。

4.  **多分支集成 (Multi-branch Integration)**：
    - **方案**：适配了 DeepSeek 最新的多分支架构（mHC）。Engram 采用“参数共享”策略：所有分支共享同一个巨大的嵌入表，但每个分支有独立的门控矩阵。这在保持模型表达能力的同时，极大提高了 GPU 的计算利用率。

5.  **硬件感知设计 (Infrastructure-aware Efficiency)**：
    - **痛点**：GPU 显存（HBM）非常昂贵且容量有限，放不下动辄上百亿参数的嵌入表。
    - **方案**：这是 Engram 的杀手锏。由于 N-gram 的索引只取决于输入的单词序列，模型可以在计算第一层时，就提前知道后面层需要哪些记忆。系统通过 PCIe 总线从廉价的 **主机内存 (RAM)** 甚至 **SSD** 中异步预取数据。实验证明，这种“空间换时间”的策略，在 100B 参数规模下，推理性能损失不到 **3%** 。

### 💡 形象比喻：Engram 到底在做什么？

如果把大模型比作一个正在参加考试的学生：

1.  **分词器压缩**：就像是把试卷上所有“苹果”、“apple”、“🍎”都统一标注为“A”，这样学生只需要背一份关于“A”的资料，而不是三份，**复习效率更高**。
2.  **多头哈希**：就像是学生怕记错，找了 8 个不同的记忆方法来背同一个知识点。即使其中一个方法记混了（哈希冲突），其他 7 个方法还能帮他**找回正确答案**。
3.  **上下文感知门控**：就像是学生在脑子里查到了“苹果”的资料，但他会先看一眼题目：如果是科技题，他就提取“苹果公司”的知识；如果是生物题，他就提取“水果”的知识。**确保不答非所问**。
4.  **硬件感知设计（异步预取）**：就像是考场允许带一本巨大的百科全书，但书太重只能放在考场外的走廊。学生非常聪明，他在做第一道题的时候，就已经想好了第三道题要查什么，于是提前让监考老师去走廊把那一页翻好。等他做到第三题时，资料已经摆在桌子上了。**完全不耽误答题时间**。

### 思考：为什么这个思路现在才被提出？

N-gram 是几十年前的老技术，为什么直到今天 DeepSeek 才把它和 Transformer 结合并取得突破？这背后有几个深层原因：

1.  **算力与存储的矛盾演变**：在 LLM 早期，大家关注的是如何增加算力（FLOPs）。但随着模型规模达到千亿级，**显存带宽（Memory Wall）** 成为了真正的瓶颈。Engram 这种“用廉价存储换取昂贵计算”的思路，在显存危机爆发的今天才显得尤为珍贵。
2.  **MoE 架构的成熟**：如果没有 MoE 这种稀疏激活的先例，直接在 Dense 模型上加一个巨大的嵌入表，训练会非常不稳定。Engram 实际上是站在了 MoE 的肩膀上，将稀疏化的思想从“计算”扩展到了“记忆”。
3.  **工程实现的突破**：异步预取（Prefetching）和多头哈希在理论上不难，但在分布式训练框架中完美实现并确保几乎零开销，需要极强的工程能力。DeepSeek 团队在系统优化上的深厚积累，是 Engram 能够落地的关键。
4.  **对 Transformer 本质的深刻理解**：过去大家认为 Transformer 的 Attention 能搞定一切。但 DeepSeek 敏锐地察觉到，让 Attention 去处理那些死记硬背的静态知识是一种巨大的浪费。这种“术业有专攻”的架构解耦，反映了对模型效率本质的回归。

## 实验结果与结论

作者通过实验发现了一个 **U 型缩放法则 (U-shaped scaling law)** ：在固定参数预算下，将约 20%–25% 的稀疏参数分配给 Engram 记忆，其余分配给 MoE 专家，能达到最优性能。

![Scaling Law](http://aisdapp.aihe.space/typora/1850dc23-778a-422f-8330-caf27f147868.png)
*图 3：稀疏性分配与 Engram 缩放。左图显示了混合分配优于纯 MoE 的 U 型曲线。*

### 主要发现：
- **全面超越 MoE 基准**：在同等参数和计算量（iso-parameter & iso-FLOPs）的情况下，Engram-27B 在 MMLU (+3.4)、BBH (+5.0)、ARC-Challenge (+3.7) 以及代码/数学领域均表现出显著优势。
- **有效增加模型深度**：机械解释性分析（LogitLens 和 CKA）显示，Engram 减轻了早期层重建静态知识的负担，使模型在早期就能形成更深层的表示，相当于增加了“有效深度”。

![Representational Alignment](http://aisdapp.aihe.space/typora/77423755-c224-40dd-990a-c32606e31454.png)
*图 4：表示对齐分析。CKA 热图显示 Engram 的浅层在功能上等同于 MoE 基准的深层。*

- **长文本能力提升**：通过将局部依赖交给查找模块，注意力机制得以释放容量来处理全局上下文。在 Multi-Query NIAH 测试中，准确率从 84.2 提升至 97.0。
- **极低的推理开销**：将 100B 参数的表存放在 CPU 内存中，推理吞吐量的损失不到 3%。

## 总结与展望

Engram 证明了条件记忆是下一代稀疏模型中不可或缺的建模原语。它不仅提高了知识存储的效率，还通过架构上的解耦，让模型能够更专注于复杂的推理任务。未来，这种将存储与计算分离的思路，可能会引领 LLM 走向更大规模、更高效的演进方向。

## 核心术语解释 (Glossary)

- **N-gram**: 语言模型中的一种基础概念，指文本中连续出现的 n 个词。
- **Sparsity (稀疏性)**: 指模型虽然拥有巨大参数量，但在处理每个任务时仅激活其中一小部分，以节省计算资源。
- **LogitLens**: 一种解释性工具，通过将模型中间层的输出直接投射到词表空间，观察模型预测的演化过程。
- **CKA (Centered Kernel Alignment)**: 一种衡量神经网络不同层之间表示相似性的数学方法。
- **Prefetching (预取)**: 在数据被实际需要之前，提前将其从慢速存储（如内存）搬运到快速存储（如显存）的技术。
